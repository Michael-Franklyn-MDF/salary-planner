# V2.1_PRD.md: Salary Planner v2.1 (UI/UX release)

## Goal

Make the app feel polished, calm and trustworthy to open every day, without changing what it does. v2 works; v2.1 fixes how it looks, moves and reads. Findings are tracked in DESIGN_AUDIT.md by ID.

## Non-goals

- No new money features (no accounts sync, no multi-currency, no charts beyond the Home ring).
- No change to how "left to spend" is calculated.
- No change to stored data shape unless the refactor needs it, and then with a migration that keeps existing phone data.

## Decisions already made

| Area | Decision |
|---|---|
| Light theme | Savanna (deep green on soft sage) |
| Dark theme | Midnight, with a lighter tint of the Savanna green as its accent |
| Style | Apple design language, clean and minimal, one accent colour |
| Theme switching | Follows the device now; settings button (top right) with Light, Dark, Follow device in a later phase |
| Greeting | Bilingual on Home, English then Spanish, swaps once, then stays. Languages stored in one list |
| Launch | Cold-start animation only. Never on tab switches. Respects reduced motion |
| Refactor | Done inside v2.1, as its own commits, before the UI work |
| Branch | `v2.1` (already on GitHub, same commit as `main`) |
| Typeface | Inter, self-hosted via `@fontsource-variable/inter` |
| Stack | Unchanged: React, TypeScript, Vite, Tailwind, shadcn |

## Phases

### Phase A: Data safety and architecture (first, separate commits)

- **A0 (release blocker):** wire storage into the app. Load on start, save on every change, and show the error screen instead of overwriting if loading fails (audit X-01). Load must run before any save, so the stored v1 data is backed up and migrated, never overwritten. Add a remount test.
- A1: one `format.ts` for money and dates (X-02).
- A2: register colours and type sizes in Tailwind `@theme` and replace the arbitrary values (X-03). This is what makes Savanna and Midnight a one-file change.
- A3: shared `Sheet`, `ConfirmDialog` and grouped-list components, and split the largest tabs (X-04).
- A4: keep unsaved input when switching tabs (X-05).
- A5: cleanup of stray files and dependencies (X-06), and refresh the docs (X-07).
- Acceptance: the app looks the same as v2, data survives closing and reopening on the phone, existing data is intact, install and offline still work. Details in ARCHITECTURE.md section 12.

## Success criteria

1. Home gives one clear answer within a second of opening.
2. A spend can be logged without scrolling, and the amount stays visible while typing.
3. The same look on Android and iPhone (bundled typeface), in light and dark.
4. No blank screen after a release: the installed app updates itself.
5. Add something, fully close the app, reopen it: the data is still there. Existing data from before the upgrade is still there too.
6. All animations are under 900 ms, never block taps, and are instant with reduced motion on.
